# GOLF JOURNAL v0.12.0 — 第12段階（最終機能統合）

本パッケージは、第1〜11段階の機能を維持した上で、**写真を含むバックアップ・復元、PWAキャッシュ更新、端末保存状態の表示と関連テスト**を追加した、静的なiPhone向けWebアプリです。ZIPにはコード、画像資材、手順書、テストが含まれます。**公開URLやiPhone実機での合格を保証するものではありません。**

## 1. PCで開発版を起動する

Node.js 18以上が必要。依存パッケージの追加インストールは不要です。

```bash
cd GOLF-JOURNAL
npm run dev
```

開発用サーバーはデフォルトで `http://127.0.0.1:4173/` に起動します。`index.html` の直接ダブルクリック（`file://`）ではIndexedDB・PWA等が正しく動かない場合があります。

**以前の版からの継続**：`golf-journal` のIndexedDBスキーマと14個のストアは維持（DB_VERSION=1）。同じ端末、同じブラウザー、同じプロトコル・ホスト名・ポートで起動すると、以前の登録データを読み込む設計です。ただし保存の実機検証は別途必要です。

## 2. バックアップする

1. 初回プロフィール登録後、ホームまたはプロフィールから「バックアップ・復元」を開きます。
2. 「写真を含むバックアップを作成」を押します。
3. `GOLF-JOURNAL-backup-YYYYMMDD-HHMMSS.json` が生成されます。
4. **「ファイル」等で実際に保存できたか確認**し、端末外の安全な場所に控えを保管してください。Safariの設定や端末の仕様によって保存方法が異なります。

保存対象は、プロフィール、クラブ、セット、ショット、コース、ラウンド、同伴者、スコア、写真の本体とサムネイル、アルバム設定、Tipsデータ、攻略条件、出典情報、設定の**14ストア全体**。写真の位置情報等は登録時の既存の再エンコード処理に依存します。バックアップは**暗号化していません**。自分や同伴者の氏名、点数、写真を含むため、共有リンクやSNSにアップロードしないでください。

ファイル内部はJSONとBase64エンコードされた画像（JPEG / PNG / WebP）。画像は基本的なシグネチャ検査と32ビットのチェックサムを使用します。これは破損検出用であり、改ざんに対する暗号学的保証ではありません。ファイル上限300MB、画像1点30MB。この上限より大きなデータを持つ場合は今後の分割／ストリームバックアップ対応が必要です。容量が大きい場合、iPhoneのメモリ不足により処理できない可能性があります。

## 3. 復元する

1. **復元前に現在のデータを別ファイルでバックアップ**してください。
2. 「バックアップファイルを選択」で本アプリのJSONを選びます。
3. 全14領域、形式、ID重複、画像形式・チェックサム、スコアの参照関係などを事前検証します。
4. 表示される件数・作成日時を確認して、「復元」と入力し、最後の確認ダイアログを承諾します。
5. IndexedDBの**全領域を単一のreadwriteトランザクションで置換**します。正常にコミットした後アプリを再読み込みします。途中でトランザクションが失敗すればDBは元の内容にロールバックされます。

**注意：これは既存データへの追加・結合ではなく、完全置換です。** インポートしたファイルが検証に失敗した段階ではデータを書き換えません。同一IDの意図しない上書きを避けるため「部分的なマージ」は実装していません。

## 4. iPhoneへの導入（未実施の最終手順）

このZIPを配布するだけではiPhoneのホーム画面にインストールできる公開アプリにはなりません。

1. 静的サイトを公開できるホスティング（例：GitHub Pages、Cloudflare Pages、Netlifyなど）へ `GOLF-JOURNAL` フォルダの**中身**を配置します。ディレクトリ階層が変わらないようにします。
2. HTTPSのURLをiPhoneのSafariで開き、プロフィール・クラブ・ラウンド・バックアップ等を実際に操作します。
3. Safariの共有メニューから「ホーム画面に追加」を選択し、追加されたGOLF JOURNALを起動します。
4. 初回のオンライン読込みが完了した状態でオフライン起動をテストします。Service Workerのアプリシェルキャッシュは `golf-journal-shell-v12` です。
5. 写真やスコアを入力して閉じ、もう一度開いた後の保存状態を確認します。JPEG / PDF、共有、バックアップ・復元も実機で確認してください。

PCの `127.0.0.1` はPC自身を指します。PC上の開発サーバーのURLをiPhoneでそのまま開いてもアクセスできません。同じLAN内のIPで一時的に画面を見る方法はありますが、一般的なHTTPのLAN IPではPWAインストールやService Workerが有効になりません。HTTPS公開を推奨します。

**ホスト移転の注意：** IndexedDBはURLのオリジン単位です。`http://127.0.0.1:4173`、`http://localhost:4173`、HTTPS公開先のデータはそれぞれ独立します。以前の環境でバックアップを作成し、新しい環境で復元してください。Safariとホーム画面追加版で保存領域が必ず共有されるとも限りません。

## 5. PWAのオフライン動作

- `manifest.webmanifest` にはアイコン、縦向き、standalone表示を設定。
- `sw.js` は全主要JS、CSS、manifest、アイコンを**アプリシェルとしてのみ**事前キャッシュします。IndexedDB内の写真・プレー記録をCache Storageに複製しません。
- オフライン時はキャッシュされたアプリシェルを利用。**初回オンライン読み込み前には動作しません**。外部ゴルフ場検索などネットワークを要する機能はオフラインでは利用できません。
- ブラウザーのストレージやキャッシュは端末の管理下にあり、OS設定・空き容量などによって削除される場合があります。定期的なバックアップを推奨。
- ストレージ容量・永続化状態は可能なブラウザーでのみ概算表示します。

## 6. 開発・テスト

```bash
npm test
python tests/ui_stage12_mock.py
```

`npm test` は191件のNodeテスト（データ、バックアップ、復元の原子性を模したDB、PWA資材）を実行します。PythonのUIテストにはPlaywright、Chromium、Pillow、pypdfなど実行環境側の追加ツールが必要です。今回のChromium UIテストは**DBをモックに置き換えた環境**で動きます。写真・PDF・JPEGのバイナリファイル生成とバックアップのダウンロードは実ブラウザー上で行います。

ローカルHTTP上の実IndexedDB永続保存とiPhone Safariはこのセッションでは未検証です。`TEST_REPORT.md` を参照。

## 7. 実装範囲と制約

第1〜11段階のプロフィール、マイクラブ、マイセット、マイショット、ゴルフ場手動登録、ラウンド、写真、Tips、攻略条件と推薦、アルバム/JPEG・PDF出力は維持しています。

**未搭載・未検証：** 全国ゴルフ場の外部API検索、メーカー公式製品横断検索、すべてのゴルフ情報の専門家監修、クラウド同期、アプリの公開代行、競技ラウンド中の自動推薦利用、iPhone実機での動作保証。ネット上の素材の無断転載はしていません。アプリの正式な競技ルール適合性は利用条件に依存します。
